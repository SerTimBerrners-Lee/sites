# Лендинг СЭП ERP

Готовая адаптивная сборка React/TypeScript/Vite. Основная страница:
`index.html`, просмотр для аннотаций шириной 390 px: `mobile.html`.
Все ресурсы имеют относительные пути; можно размещать в `/ERP/` или корне сайта.
Исходный фронт и его тесты находятся в локальном проекте SEP. Изменения делаются
в исходниках, затем `npm run build:erp` и `npm run check:erp`.

## Заявки

Все три формы подключены к `POST /api/leads` на том же домене, с проверкой полей,
согласия, ожиданием ответа, блокировкой дублей и сохранением данных при ошибке.
Успех показывается только после подтверждения SMTP сервером.
Отправитель и получатель: **info@pksep.ru**. Email посетителя только в Reply-To.

После успеха вместо формы плавно появляются зелёная галочка и подтверждение
из Figma. Высота блока и положение страницы сохраняются; через 10 секунд
возвращается пустая форма. При ошибке отправки введённые данные не очищаются.
Это поведение общее для двух форм на странице и формы в модальном окне.

Отдельный запускаемый backend: `backend/erp/` в корне репозитория sites.
Инструкция DevOps, серверный ENV-шаблон, nginx и systemd: `deploy/erp/`.
Для backend нужен Node.js 24.13+, SMTP-пароль в серверном ENV и постоянная SQLite.
**Одна статическая сборка не включает отправку писем.** Backend необходимо
развернуть и подтвердить реальную доставку тестовых заявок на info@pksep.ru.
Локальные автоматические тесты не отправляют реальных писем.

Публично размещать только эту папку, не backend, deploy, ENV, БД и зависимости.
Не добавлять пароли в клиентский JS, Git или логи. Наличие файлов в Git не
подтверждает выкладку и готовность приёма заявок на pksep.ru.

Демо-ассистент отвечает локально готовым сценарием, не выполняет действия в ERP.
Ответ сокращён до приветствия и приглашения на демонстрацию в двух баблах;
кнопка записи расположена под ними.
Юридические документы в окнах пока черновики и требуют утверждения.
